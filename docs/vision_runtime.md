# BlendPilot Vision Critic Runtime

This document details how the Vision Critic (Stage 11) evaluates rendered Blender images using visual LLMs.

## 1. Vision Model Used
The pipeline supports multiple providers and automatically maps to their flagship vision models:
- **OpenAI**: `gpt-4o`
- **Anthropic**: `claude-3-5-sonnet-20241022`

(Defined in `services/llm.py` under `LLMService.VISION_MODELS`)

## 2. Provider/API
The API integration uses **LangChain** (`langchain_core.messages.HumanMessage`) to interface with the providers using a standardized multimodal payload structure.

## 3. Required Environment Variables
The system requires a valid API key to run real vision inference:
- `OPENAI_API_KEY` (if using OpenAI)
- `ANTHROPIC_API_KEY` (if using Anthropic)

These are usually provided via the `.env` file or environment variables.

## 4. Vision Critic Inputs
The Vision Critic agent is supplied with two main sources of text context:
1. **Original Intent (`DesignSpec`)**: `asset_type`, `style`, `dimensions`, `materials`, `description`
2. **Scene Summary**: A quick count of objects and materials retrieved directly from Blender.

## 5. Image Input (`preview.png`)
Yes, the agent receives the actual render. The pipeline passes the absolute path of `preview.png` (generated by the render node) to the vision generation function.

## 6. How the Image is Transmitted
The image file is read from the local disk in binary mode (`rb`), encoded into a base64 string, and attached to the LangChain `HumanMessage` using the standard data URI scheme:
`"image_url": {"url": "data:image/png;base64,{b64}"}`

## 7. Expected Response Schema
The LLM is prompted to return a raw JSON string (without markdown fences) adhering exactly to the `VisionReport` Pydantic schema:

```json
{
    "object_presence": true/false,
    "required_component_presence": true/false,
    "color_match": true/false,
    "approximate_shape_match": true/false,
    "obvious_visual_errors": ["list of strings"],
    "confidence": 0.0 - 1.0,
    "overall_result": "PASS" or "FAIL"
}
```

## 8. Missing API Key Behavior
If the LLM Service detects that the `api_key` is missing (or if `mock_mode` is explicitly set to `True`), the system completely bypasses the LangChain API call. It instantly returns a hardcoded mock `VisionReport` where:
- All boolean checks are `true`
- `obvious_visual_errors` is empty `[]`
- `confidence` is exactly `1.0`
- `overall_result` is `"PASS"`

## 9. Distinguishing Real vs. Mock Results
Programmatically, the system relies on the presence of the `api_key` to determine whether to execute the real API call or return the mock result. Within the generated data structure, a mock result can be recognized by its perfect scores (all fields true, exactly 1.0 confidence, and no errors).

---

## Minimum Configuration for Real Execution
To force the system to perform a genuine Vision Critique instead of the mock fallback, the following configuration is the absolute minimum:

1. A valid API key in the `.env` file:
   ```env
   OPENAI_API_KEY="sk-..."
   ```
2. The real render pipeline must successfully output a valid `preview.png` (which was resolved in the previous stage).
